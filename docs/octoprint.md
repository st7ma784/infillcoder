# OctoPrint plugin

## Installation

See [Deployment](deployment.md) for full installation instructions.  The short version:

```bash
make dist
# then upload octoprint_plugin/dist/infillcode-0.1.0.tar.gz via Plugin Manager
```

---

## Configuration

Open **Settings → InfillCode** after installing the plugin.

| Setting | Default | Description |
|---------|---------|-------------|
| **DB path** | *(empty)* | Absolute path to the `.db` file downloaded from the web tool |
| **Snapshot URL** | *(empty)* | OctoPrint webcam snapshot endpoint, e.g. `http://localhost:8080/?action=snapshot` |
| **Nominal spacing (mm)** | `0` | Set to the infill spacing used when encoding (0 = auto-detect) |
| **Spacing tolerance** | `0.15` | Acceptable deviation ±15 % for SYNC / bit classification |
| **Auto-resume** | ✓ | Generate remainder GCode automatically on `PrintFailed` |
| **Z-hop (mm)** | `2.0` | Nozzle lift before moving to resume position |
| **Prime length (mm)** | `20.0` | Filament extruded to purge before resuming |

---

## Events

The plugin registers for three OctoPrint events:

| Event | Action |
|-------|--------|
| `PrintFailed` | Snapshot → decode → DB lookup → sidebar message; if Auto-resume is on, generate resume GCode |
| `PrintDone` | Snapshot → decode → DB lookup → sidebar message |
| `PrintCancelled` | Same as `PrintDone` |

All processing happens on a daemon thread so OctoPrint is never blocked.

## Sidebar panel

The **InfillCode** panel appears in the OctoPrint sidebar.  After a print event it
displays:

```
InfillCode
──────────────────────────────
Event:       PrintFailed
File:        mypart_infillcode.gcode
Layer:       42 / 100
Z height:    8.40 mm
Progress:    42.0 %
Filament:    150.5 mm
```

If a resume file was generated:

```
Resume file: mypart_resume_from_layer_43.gcode
Resume layer: 43  (Z = 8.60 mm)
Layers remaining: 57
```

## Auto-resume

When `Auto-resume` is enabled and a `PrintFailed` event fires, the plugin:

1. Locates the original GCode file (via the event payload path, then an uploads
   directory scan, then the DB's sibling directory).
2. Calls `core.resume.build_resume_gcode()`.
3. Saves the result next to the original file (falls back to the uploads root).
4. Registers the new file with OctoPrint's file manager so it appears immediately
   in the file list.

### Resume GCode structure

The generated file begins with an init sequence extracted from the original preamble:

```gcode
; InfillCode resume — mypart.gcode — from layer 43 (Z=8.60mm)
; Generated by InfillCode 0.1.0

; --- Restore printer state ---
M104 S200   ; set hotend temperature (non-blocking)
M140 S60    ; set bed temperature (non-blocking)
M82         ; absolute extruder mode
G21         ; millimetres
G90         ; absolute positioning
M109 S200   ; wait for hotend
M190 S60    ; wait for bed

; --- Move to resume position ---
G91
G1 Z2.0 F600    ; z-hop
G90
G1 X5 Y5 F6000  ; move to prime corner
G1 Z8.60 F600   ; descend to resume Z

; --- Prime nozzle ---
G1 E20.0 F1500  ; prime 20 mm
G92 E0

; --- Resume print from layer 43 ---
<remaining GCode verbatim>
```

## Troubleshooting

**The sidebar shows "DB path not configured."**
: Set the **DB path** setting to the absolute path of the `.db` file you downloaded
  from the web tool.

**The sidebar shows "Could not extract spacings from snapshot."**
: The vision pipeline could not find enough parallel lines.  Check that the snapshot
  URL is correct and the print surface is visible.  Try increasing the nominal spacing
  when encoding (larger gaps are easier to detect).

**The sidebar shows "Decoded file_id=X layer=Y but not found in DB."**
: The decoded fingerprint does not match any layer in the database.  Make sure you are
  using the `.db` file that corresponds to the GCode file you printed.

**Resume file not appearing in the file list.**
: The file was saved to disk but OctoPrint's file manager registration failed.
  Manually refresh the file list or look in the uploads directory for a file named
  `*_resume_from_layer_*.gcode`.

## Plugin message format

The plugin sends messages to the frontend via OctoPrint's plugin messaging system.
JavaScript in `infillcode.js` receives these and updates the sidebar:

```javascript
// Error
{ "type": "error", "message": "DB path not configured." }

// Success
{
  "type":            "layer_identified",
  "event":           "PrintFailed",
  "filename":        "mypart_infillcode.gcode",
  "layer_idx":       42,
  "total_layers":    100,
  "z_height_mm":     8.4,
  "pct_complete":    42.0,
  "cumulative_e_mm": 150.5,

  // Present only if auto-resume succeeded:
  "resume_file":       "mypart_resume_from_layer_43.gcode",
  "resume_file_path":  "/path/to/file",
  "resume_layer_idx":  43,
  "resume_z_mm":       8.6,
  "layers_remaining":  57
}
```
